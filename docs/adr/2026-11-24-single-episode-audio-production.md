# ADR：凡人说书单集音频制作与验收

**状态：提议，待评审｜日期：2026-11-24｜范围：凡人说书项目的完整单集音频制作与验收，不含公开发布。**

**建议：一集一张 Multica Issue、一名具名主责、一次交清整集目标。** 卡内按场景或完整话轮推进，可以跨 Run、有条件并行。首件用一个代表性场景验证从台本到成音和字幕的链路；这不是另一次交办，也不拿首件替代整集验收。

## 旧流程复核

**应保留。** 从路线图锁定本集的原文章节、核心冲突、剧情止点和上下集衔接；再做演义稿及独立复审，派生分角色台本，冻结正文、完整话轮、角色声音和依赖版本。合成后做音频和字幕核验，按版本交付。已有分集实践将母带、成品、字幕和制作说明分别交付，也将空间齐备、本地复制和人工听审分别记录。

**需要纠正。** 旁白技术预览不是含角色的整集音轨。用旧稿和旧段号统一搜齐素材，会把可复用参考变成开工依赖。单句实跑验证了生成、技术核验、独立模型听审、主责核收和回程，但不能推出逐字一致、参考声身份、人耳听审或生产放行。运行会话不满足启动条件时，静态预检通过也不等于可以实际生成。首次运行才会产生的记录不能当成开工前提。

**质量反例。** 历史角色配音复盘坐实的是跨话轮听审漏检，不是已证明“没有参考音导致换声”。同预设或同 seed 不能证明听感一致。先对照同角色锚点，再回听最终上下文；只修证实有问题的完整话轮，若问题在后期就只修后期。

## 备选方案和取舍

| 方案 | 好处 | 代价与结论 |
| --- | --- | --- |
| 台本、配音、核听、混音分别开卡 | 各岗位有独立队列；适合独立交付、明确不同主责 | 容易多次交办、断开验收范围；不作为默认 |
| 冻结后直接全量生成，最后一次核听 | 调度简单 | 错声、字幕或拼接问题发现晚，返工扩大；只适合已验证的同配置补件，不用于新模式首单 |
| 一集一卡，代表性首件后分批 | 执行早发现问题，主责有始有终，故障可从批次断点恢复 | 多一次小规模核对、需维护分段清单；推荐，清单只记影响交付的字段 |

## 决策：按交付而非动作建任务

1. **一次写齐目标。** 绑定节目、篇章和稳定集 ID，写清原著范围、上下集接缝、采用的路线图、目标成品、工期、产物位置、主责及独立验收人。新制整集以实际音轨 **≤20 分钟**为硬上限，12–18 分钟只作预算。默认交 WAV 母带、MP3 成品、最终 SRT、核验说明与清单；封面、MP3 内嵌封面按本卡选项验收。交付不等于上传、生产导入或发布。

2. **台本冻结后才进入正式合成。** 先从零建立本集结构，独立或交叉复审实际全文及完整说话归属；标签、情绪指令不朗读。素材清单标为现版可用、历史参考、缺失、待核；同台词、同角色、采用版本和声音契约均匹配且适用范围获准才复用。缺失则为新版补做，不强把新稿贴到旧段号。文本、封面等独立工作不等音频问题解决。

3. **用代表性首件验证本次变更。** 首件开工前核当前获准入口、执行身份和可用会话、按声线契约所需的参考音及逐字稿、写入落点和防覆盖，以及核听人的实际访问能力。首轮产物与日志留到运行后核收。新声线、新入口或新拼装路径从冻结台本取最短的代表性片段，保留需要判断的完整话轮和接缝，走该批次拟用的实际链路。按本次影响覆盖旁白、人物切换、专名或停连。新声线对照同角色锚点，回听该角色在不同话轮的声音一致性。新拼装路径用实际成音核接缝和字幕时码。

   **放行条件。** 约定的核听人实际核听首件，在原卡记录产物版本、覆盖范围和结论。已有通过证据在配置与验证范围仍适用、产物和记录均可读回时可直接引用。在当集相应范围已获正式生产许可的前提下，首件通过或引用了适用的通过证据后，才启动依赖它的正式批次。待核或未通过只暂停受影响批次，其他已获准且无此依赖的工作继续。

4. **按场景生成、验收和修订。** 台本与音色基线冻结后，按完整话轮组织批次。不同场景和可独立工序可以并行，共享 GPU 沿既有互斥。在原 Issue 记录集与批次 ID、场景与话轮 ID、冻结输入版本及摘要、Run 引用、输出及摘要、状态、验收结论和例外。同一批次换 Run 时沿用批次 ID、冻结输入和已获授权，追加执行记录并保留已核产物。结果未知时先对照原卡、执行日志、在途运行和实际文件，确认原动作已无待执行或运行中的请求后只补确缺部分。同一问题保留一位主责、下次复查点和恢复条件。

5. **按整集收口。** 逐段覆盖核对，核（必要时双路识别辅助）漏重、错声、截尾和术语；独立听审按约定明确实际覆盖、方法与保留，跨句声线、人物切换、响度跳变和场景接缝必须有对应证据。最终 WAV 与 MP3 可全解码，字幕据最终音频真实时码重核，无越界、反序或重叠；检查响度、削波和段间一致性，按现版方案处理，不给成品重复叠加历史 B 后期。记录具体成品版本、路径、时长、摘要和验收结论，保存原始配音、可恢复母带与失败对照。只有整集验收人按约定范围签认，原卡才记整集完成；需审批的公开发布另行处理。

**与现有工作流的关系。** 新批次沿 Multica 原 Issue 和对应 Run 接续，在原卡核收实际工件和验收结果。[episode-delivery](../../workflows/episode-delivery/README.md) 用于具备其原生回执的单元。它在初始化或绑定时校验 Herdr 投递回执，收件时读取绑定回合的 Codex 原生 final 并核对工件摘要，负责人决定只覆盖该单元。

已由该工具绑定或接续的原生动作沿原动作对账和核收。每个独立单元使用自己的稳定 `task_id` 和私有检查点。恢复沿原检查点、冻结输入和固定源码。修订或改变交付范围时，以新的 `task_id` 和检查点建立后继单元并引用原单元。单元及批次记录挂在同一集的原 Issue，[08-01 历史接续](../../workflows/episode08-01-continuation/README.md) 沿其既有定义执行。

## 建卡模板

**标题**：《脚滑的小子》｜〈篇章〉〈集号〉〈题名〉｜整集音频制作与验收

**交付**：最终 WAV、MP3、SRT、台本版本及核验清单；封面和嵌入要求另填；不含发布。**主责**：〈现任项目负责人〉；**独立验收**：〈具名人员／约定方式〉。

**输入**：本集路线图 ID 和版本、原著起止及剧情接缝、说书与配音规范入口、角色声线基线、素材清单、已批准的执行入口及输出目录。

**卡内检查点**：台本复审与冻结 → 首件核听通过或确认适用证据 → 分批生成和独立核听 → 整集拼装、字幕及试听 → 指定验收人签认并归档。每点在原卡记录交付物、例外、主责与复查点。出现变化只升级实际受影响的许可或决定。

## 验证与回退

在下一张本来就要制作的整集原卡试用；不另建演练工单。观察从冻结到首个可用场景的耗时、无效等待及重复生成次数、听审后返工话轮占比、整集验收覆盖。小样失败时只暂停受影响的声线或路径；回退到上一次已核实的输入和母带，保留失败对照。若分工确实变成不同主责的独立交付，再拆卡并链接父 Issue。既有小样按原任务继续，本 ADR 不扩大任何制作或发布授权。
