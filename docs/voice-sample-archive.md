# 角色配音样片归档

已在原任务确认采纳的角色配音样片，由负责人核对采用证据，安排该任务的素材写者将获准按仓库可见性存放的精确版本归入项目仓库。本规则适用于作角色音色参考的样片。角色正片台词、整集成品、试音候选与制作中间文件沿各自既有保管入口处理。既有项目复核规范和正式记录入口见 [Issue #2](https://github.com/CF-FE/fanren-work/issues/2)。

1. **核准同一份样片。** 原任务须能追溯角色、具体样片和采纳决定。原决定可用文件摘要或可唯一解析到原件的附件、工件或版本引用标识样片。公子的实际试听与意见沿同一原任务记录；有实际试听要求时，核对播放文件与反馈的对应关系。收件、播放与负责人采纳分别记实。已有同版本采纳记录可直接复用。逐件核来源和许可是否覆盖项目仓库的实际可见性。未能唯一定位原件、许可范围待核或证据冲突时，沿原任务列明该件缺口，其他已核清的样片继续归档。
2. **保存原字节与索引。** 以角色登记中的稳定 ID，在 `assets/voice-samples/<role-id>/<version>.<ext>` 存该样片的精确字节，同一提交更新 `assets/voice-samples/index.json` 的 `samples` 数组。引用使用仓库根相对路径或原任务中的稳定记录编号；每件记录 `role_id`、仓库相对 `path`、`bytes`、`sha256`、`adoption_ref` 和 `source_ref`；来源记录和许可依据分开时再记 `permission_ref`。版本由路径表达；引用指向原记录，公开索引只放获准公开的标识，内部引用可用原任务持有的可追溯编号。原件、播放副本和转码各按自己的字节识别。相同角色、同一采纳版本和同一摘要复用原记录。
3. **在目标回读。** 从正式仓库的准确提交读取索引和完整样片，逐件核对字节数及 SHA-256 与已采纳原件一致，在原任务留下提交、样片路径和逐件结果。上传、回读、试听和验收各自依据实际证据。部分完成时保留成功项，沿同一任务补已确认缺项。
4. **替换与撤销。** 重做或替换沿原任务确认新版本的样片、许可及采纳，再用新路径归档。原任务明确替换关系和当前引用；撤销时更新当前索引与引用，保留受控的原决定记录。旧提交仍可能含原文件。涉及公开撤回或删除时，由负责人沿原任务核定处置及结果。归档记录用于找回和校验固定样片。角色音色克隆、台词合成和成品交付由相应制作合同与权限放行。

凡人项目定位开源，本仓为公开仓库。公子于 2026-11-13 明确已确认采纳的角色样片归档项目仓库、允许公开下载；此为后续同范围归档的持续依据，不逐件重复请求已覆盖的公开许可。明确的第三方来源或用途限制仍按原约定核对，缺项仅影响对应材料。正式整集成品的 Win 归档规则继续适用；样片归档不扩大声音克隆、新台词合成或成品发布权限。
